## 1. 試合の流れ（決定 2026-10-11 芦田）

```
ホーム（参加者を決める）
  └→ ミニゲームをランダムに選ぶ（演出なし）
       └→ ラウンド（ひと言の指示とカウントダウン → ミニゲーム → FINISH）
            └→ ミニリザルト（勝った人のライトが1つ点く。3秒で自動で次へ）
                 ├→ だれも2勝していない → 同じミニゲームの次のラウンドへ
                 └→ だれかが2勝した → そのミニゲームの勝者
                      └→ リザルト（階段：勝者が1段上がる。4秒で自動で次へ）
                           ├→ だれも一番上に着いていない → 次のミニゲームへ（ランダム）
                           └→ 一番上（2段）に着いた → 総合優勝「勝者 ○○」→ PCの「ホームへ戻る」でホームへ
```

| 項目 | 決定 |
|---|---|
| ミニゲームの勝者 | 同じミニゲームを何ラウンドも遊び、**先に2勝した人**（2026-10-12 に3勝から変更。1つのゲームを長く続けるより、いろいろなゲームで階段を上がる方が楽しいため。野上） |
| 総合優勝 | 階段は**2段**。ミニゲームに2回勝った人（一番上に着いた人） |
| 次のミニゲーム | **ランダム、演出なし**。同じ試合の中では、全部遊ぶまで同じゲームを選ばない |
| 参加者 | ホームで最初に決める。**試合の途中で来た人は、次のラウンドの始めから加わる**（下の「途中参加」。2026-10-12 野上の依頼で変更。以前は途中で人数は増えなかった） |
| 画面の進め方 | ラウンドの合間（ミニリザルト3秒・リザルト4秒）は**自動で次へ**。総合優勝だけ PC の「ホームへ戻る」 |
| ミニゲームの説明 | 「ゲーム紹介」の画面は**入れない**。代わりに「避けろ！」「高く跳べ！」「生き残れ！」などの**ひと言の指示**だけを出す（ミニゲームごとに決める） |
| 画面の状態の名前 | `lobby`・`playing`・`miniResult`・`result`・`champion`（`messages.ts` の `Phase`。M4） |
| 操作 | スマホの**3ボタン（左・右・ジャンプ）だけ**。ジャンプボタンを「決定」「投げる」など別の意味で使うのはミニゲームごとに自由。コントローラーと `messages.ts` の入力の形は変えない |

### 画面
| 画面 | 内容 |
|---|---|
| ミニリザルト | 毎ラウンドの後。キャラを**最大2列**に並べ、1人に**信号のようなライトが2つ**。勝つたびに1つずつ点く。2つ点いた人がそのミニゲームの勝者 |
| リザルト | ミニゲームの勝者が決まった後。**階段**にキャラを並べ、勝者が1段上がる。一番上に着いたら総合優勝 |

### 再接続（Q4。決定 2026-10-11 芦田、M12 で実装）
**同じスマホでの復帰だけに対応する。** 別のスマホでの引き継ぎ、PC の再読み込みからの再開はしない。

- スマホの playerId は `localStorage` に保存する。タブを閉じても、同じスマホで QR を読み直せば同じプレイヤー（番号・色・名前）に戻る
  - 以前は `sessionStorage` に保存していて、タブを閉じたり iPhone がタブを破棄したりすると別人扱いになっていた（M12 で変更）
- 試合の参加者は開始時に決める（途中で来た人は下の「途中参加」のとおり加わる）。接続が切れても枠・番号・色は消さない
  - 「切断中」の表示は出さない（2026-10-11 野上の判断、M12）
  - 試合中は、スタートの時点の参加者（M5）を使うので、切れても番号と色は外れない。名前も最後に分かっていたものを使う（M12）
- 切断中の人のキャラはその場に残し、操作だけ止める（入力は「何も押していない」扱い）。勝敗の計算には残す
- 切れた人を待たずに試合を進める（ほかの人を止めない）
- そのスマホが使えなくなった人は、その試合には戻れない（キャラは残る）

### 途中参加（2026-10-12 野上の依頼。芦田の確認待ち）
試合の途中でQRを読んだ人も、**次のラウンドの始めから**一緒に遊べる。

- 遊んでいる最中のラウンドには入らない（ミニゲームは参加者をラウンドの最初に決めるため）。ミニリザルト・リザルトが終わって次のラウンドが始まるときに加わる
- 勝ち数（ライト）も階段の段数も **0 から**始める
- 番号と色は、空いている一番小さいものを割り当てる。切断中の参加者の番号は空きにしない（Q4 で枠を残すため）。8人で満員なら加わらない
- 総合優勝が決まった後は加わらない（ホームに戻ってから参加）
- 待っている間、スマホには「次のラウンドから参加！少し待ってね」と出す
- ホームに戻っても、途中で加わった人の番号と色は変えない

## 2. 作りの方針

### ミニゲームの共通の形
どのミニゲームも、**同じ受け渡し**で試合の流れにはめ込めるようにする（Jump the highest の `GameScreen` の形を広げる）。

- 受け取るもの：参加者（`playerId`・番号・色・名前）、今のボタン状態（`getInputs`）
- 返すもの：ラウンドが終わったら1回だけ、**勝った人の一覧**（`winners: string[]`。複数なら引き分け）
- ミニゲームごとに持つ情報：id、名前、**ひと言の指示**（例：「避けろ！」）

試合の進行（何勝したか、何段目か、次に何を遊ぶか）は**ミニゲームの外**（試合の進行の部品）で管理する。ミニゲームは1ラウンドのことだけを考えればよい。

### フォルダの分け方（予定）
| 場所 | 中身 | 主な担当 |
|---|---|---|
| `src/engine/` | ゲーム共通の部品（スクロール・足場・ポイント・脱落・当たり判定） | 芦田 |
| `src/audio/` | 音 | 芦田 |
| `src/games/<ゲームのid>/` | **ミニゲーム1本ずつ**。ほかのミニゲームのフォルダを触らない | 1本ずつ担当を決める |
| `src/platform/` | 試合の進行、ミニリザルト、リザルト（階段）、ミニゲームの登録 | 進行は芦田、画面は野上 |
| `src/pages/` | PC画面・スマホ画面（画面の切り替え） | 野上 |
| `src/game/` | Jump the highest（今の場所のまま。ほかのミニゲームと同じ形で登録する） | 芦田 |

### 2人の AI（Claude Code）で並行して進めるためのルール
- **触るフォルダを分ける**。ミニゲームは1本＝1フォルダ＝1担当
- **共通の形・`messages.ts`・試合の進行**のように両方に影響するものは、先に作って main に入れてから、その上に積む（タスク表の「前提」を守る）
- 部品を作り直さない。作る前に [部品一覧.md](部品一覧.md) を読む。足りなければ部品の側に足す
- 1タスク＝1PR、**PRは必ず main 向け**（積み重ねない）
- 実装 → テスト・ビルド・lint → ローカルで確認 → 人が「OK」と言ってから push・PR

### うまくいったやり方（続ける）
| やり方 | 理由 |
|---|---|
| 計算は純粋な関数にしてテストを書く。**わざと壊してテストが失敗するか**も確かめる | テストが甘いと、通っていても不具合を見逃す（足場の着地判定で実際にあった） |
| ブラウザ（Playwright）で実際に動かして確認する | テストでは見つからない不具合（頭の端に浮く、滑り落ちた直後に弾かれる）がブラウザで見つかった |
| サブエージェントにコードレビュー・ブラウザ確認を任せる | 「下の人が空中にいると上の人が置いていかれる」重大な不具合を発見できた |
| 素材ファイルを使わず、音をプログラムで作る | 素材サイトの規約（Web ゲームでの利用・再配布）の問題を避けられる |

### 起きた問題と対策
| 問題 | 対策 |
|---|---|
| 積み重ねたPR（#9〜#11）が main ではなく前のブランチにマージされ、main に届かなかった | **PRは必ず main 向け**にする |
| 開発サーバーが動いたまま `npm ci` してファイルのロックで失敗した | `npm ci` の前に開発サーバーを止める（Windows） |
| 同じファイルの同じ場所に2つのPRが追記してコンフリクトした | 追記する場所をずらす。マージ前に `git merge-tree` で確かめる |
| Presence の更新がPCに届くまで約3秒かかった | すぐ反映したい情報は Broadcast でも送る（名前の変更で対応済み） |
