# 初期構想

## 作りたいもの
対戦型のゲーム
「ピコゲーム]・ハコボーイのようなシンプルなUIで作成すること。
スマホをコントローラーとして操作が可能で、PCを操作画面とする
最初プレイ人数が2人で最大は8人

### 画面構成
ホーム画面・ゲーム画面・リザルト画面の３画面をミニマムで作成する。
ホーム画面では、参加人数を**スマホの接続数から自動で決める**（人数選択の操作はしない）。ゲームの種類が増えてきたら、ゲームを選択できるようにする

### 最初に作るゲーム

「Jump the highest」というゲームを作成する。
制限時間内（10秒）で自由に動き回ることが出来き、終了時間になったとき、最も高い地点（y軸）にいるプレイヤーを勝者とするゲーム。

#### 勝敗判定

- **終了した瞬間の高さ**で判定する（空中にいても有効）。最後のジャンプのタイミングを競う要素になる。
- 最も高いプレイヤーが複数いる場合は**引き分け**とする。

### 可能な操作・仕様

- ジャンプ
- 横移動
- 他の人の上にのる（頭の上にのる）
  - 下の人が動いたとき、**上の人は一緒に運ばれる**
- 頭の上でのジャンプも可能
- 横からぶつかった場合は、横斜め上方向にはじけ飛ぶ
  - お互いが動いているときは**両方が弾かれる**

#### スマホ操作

- スマホは横もち
- ボタン式の操作
  - 横移動（右・左）
  - ジャンプ
- ジャイロはいったんオフ
- Android・iPhone両方に対応すること

### ステージ

固定、障害物なしの地面だけ存在する場所
落ちたりもしない。横には壁が存在しているので、無限には移動できない
全員が同じ部屋にいる前提で作る

## 技術スタック

方針：**すべて無料の範囲で構築する。** 自前のサーバーは持たず、静的サイト＋Supabase Realtimeで通信する。

| 役割 | 技術 | 使い方 |
|---|---|---|
| 言語 | TypeScript | 全体 |
| フレームワーク | Vite＋React | PC画面とスマホのコントローラー画面を1プロジェクトで作る |
| 公開先 | Vercel（Hobby・無料） | GitHubにpushすると自動で公開 |
| 通信 | Supabase Realtime（無料プラン・東京リージョン） | Broadcastで操作を送り、Presenceで参加人数を管理 |
| 描画 | HTML5 Canvas | 2Dのシンプルな図形やドット絵 |
| 物理処理 | 自作（ライブラリなし） | 重力・ジャンプ・横移動・床/壁/プレイヤー同士の当たり判定 |
| 見た目 | Tailwind CSS＋ドット風フォント（DotGothic16など） | ピコゲーム風のUI |
| QRコード | qrcode.react | ホーム画面にコントローラー用URLを表示 |
| コード管理 | GitHub（公開リポジトリ） | https://github.com/shumanogami/workworkpark 共同編集者として参加済み |

### 実行環境

```
[スマホ(ブラウザ)] ──ボタン入力──▶ [Supabase Realtime] ──▶ [PC(ブラウザ)]
   コントローラー役                    中継(クラウド)              ゲーム本体・物理演算・描画
```

- **PCがゲーム本体（審判役）、スマホは入力を送るだけのリモコン。** 物理演算はPCだけで行う。
- スマホはアプリ不要。QRコードを読んでブラウザで開くだけ（iPhone・Android共通のコード）。
- PCはブラウザ（Chrome推奨）でゲーム画面を開く。
- 開発時にPCへ入れるもの：Node.js（LTS版）、VSCode。
- 部屋はチャンネル名（例：`room:ABCD`）で分け、QRコードのURLにルームコードを含める。
- 参加人数はPresence（接続中のスマホ数）から自動で決まる。

### 実装ルール

- **送信の設計**：ボタンの「押した」「離した」を変化時に送信し、加えて**ゲーム中のみ0.5秒ごとに現在のボタン状態を送り直す**（「離した」が届かずキャラが走り続けるのを防ぐ）。8人で毎秒16件程度に抑え、無料枠の毎秒100件に余裕を持たせる。
- **キーの管理**：SupabaseのURLと`publishable key`（`sb_publishable_`で始まる。旧`anon key`は2026年末で廃止予定）は`.env.local`に`VITE_`で始まる名前（例：`VITE_SUPABASE_URL`）で書き、`.gitignore`で除外する。Vercelの環境変数にも同じ名前で登録する。**`secret key`（旧`service_role`キー）は絶対にコードやリポジトリに入れない**（公開リポジトリのため）。
- **URLの直接アクセス**：QRコードから`/controller?room=ABCD`のようなURLを直接開くため、Vercelで404にならないよう`vercel.json`に「すべてのパスを`index.html`へ返す」設定（rewrites）を入れる。
- **スマホのボタン**：`touch-action: none`を指定する（ダブルタップでの拡大やスクロールを防ぐ）。
- **画面の向き**：iPhoneのSafariは横向き固定に非対応のため、縦向きのときは「横にしてね」と表示する。
- **ゲームループ**：`requestAnimationFrame`は`useEffect`内で起動し、クリーンアップで必ず止める（開発モードでは`useEffect`が2回実行されるため、止め忘れるとループが二重に動く）。
- **物理処理の見込み**：プレイヤーが積み重なるときの処理（上の人を一緒に運ぶ、多段の当たり判定の解決順）に手間がかかる。150〜300行を見込む。
