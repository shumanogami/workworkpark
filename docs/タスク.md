## 分担の考え方

| 担当 | 範囲 | タスク | 触るファイル |

| 芦田 | **ゲームの中身**（物理・描画） | T6〜T9 | `src/game/` |

| 2人 | 最初の取り決めと最後の仕上げ | T2、T13、T14 | ― |

- 触るファイルを分けて、同じファイルの同時編集（コンフリクト）を避ける。
- 最難関のT8が芦田側にあるため、軽めのタスク（T5、T10、T12）は野上側に寄せている。
- 2日目の昼の時点でT8が終わりそうになければ、T9を野上に渡す。

### つなぎ目の取り決め（芦田 ⇔ 野上）

芦田が `src/game/` に作る `GameScreen` コンポーネントを、野上が `HostPage` のゲーム画面で表示する。受け渡しは次の形とする（T6で仮実装し、2人で合意して確定する）。

```tsx
<GameScreen
  players={players}          // 野上 → 芦田：参加者（playerId と色）
  getInputs={() => inputs}   // 野上 → 芦田：今のボタン状態（playerId → InputMessage）
  onFinish={(heights) => …}  // 芦田 → 野上：10秒後の各プレイヤーの高さ
/>
```

勝敗判定（高さの比較・引き分け）は、`onFinish` を受け取った野上側（T10）で行う。

### 芦田担当（Claude Code）の進め方

- タスクごとにブランチを切り、**1タスク＝1PR** で出す（T6 → T7 → T8 → T9）。
- 各PRで芦田がキーボード操作で動作を確認し、野上がレビューしてからマージする。
- 実装中に決まっていない仕様が出たら [未決定仕様（芦田）.md](未決定仕様（芦田）.md) に追記し、仮の対応で進める。

## 各タスクのメモ

- **T2**：`messages.ts` は現在の型で確定（2026-10-10）。Supabase・Vercelの準備も完了。公開URLは https://workworkpark.vercel.app 。環境変数 `VITE_SUPABASE_URL`・`VITE_SUPABASE_ANON_KEY`（値は publishable キー）を Production・Preview の両方に登録済み。
- **T3**：`playerId` は `crypto.randomUUID()` を使わない（https以外では使えず、`http://192.168...` での開発時にスマホでエラーになる）。`Math.random().toString(36).slice(2)` などで作り、`sessionStorage` に保存して再読み込みでも同じIDで復帰させる。
  - 実装済み（2026-10-11）：番号と色は `src/lib/players.ts` の `assignPlayers` で決める。一度決まった人の番号・色は変えず、抜けた人の番号は次に来た人に回す。9人目以降は割り当てず、空きが出たら入れる。スマホ側に自分の色・満員を伝える方法は U4 として未決定（T12 で決める）。
- **T4／T7**：ジャンプの短いタップを見逃さないよう、PC側は `jump: true` を受け取ったら「次のコマでジャンプする」予約フラグを立てる。
- **T9・T12**：決まっていない仕様がある。[未決定仕様（芦田）.md](未決定仕様（芦田）.md) を参照。
- **T11**：iPhoneのSafariは横向き固定に非対応。縦向きのときは「横にしてね」と表示する。
- **T13**：会場の共有Wi-Fiでは端末同士の通信が遮断されている可能性がある。実機テストは**VercelのURL**で行い、スマホはモバイル回線でもよい。予備としてテザリングを用意する。
- **`messages.ts` を変更するとき**：もう1人（芦田・野上）に一声かける。デプロイ後はスマホのページを再読み込みする（開きっぱなしのスマホは古いコードのまま動くため）。
