# マグマラッシュ 調整ログ・引き継ぎメモ

最終更新：2026-10-12（調整の周回はまだ始めていない。準備の途中で中断）

## 目的

ボット（自動で操作する仮のプレイヤー）に大量に遊ばせて数字を測り、10周くらい「測る → 直す → 確認」をくり返して、楽しい難易度にする。

## 進め方（1周）

1. **測る**：上手・普通・下手なボットで何千試合も回し、次を集計する
2. **直す**：目標から外れた数値を `constants.ts`（と `stage.ts` の段の高さ・足場の数）で調整する
3. **確認する**：`npm test` と `npm run build` を通す。必要なら `/dev/magma-rush` を開いて見た目を確かめる
4. **記録する**：ローカルでコミットし、このファイルの「周回の記録」に「測った数字・変えた値・理由」を足す

push とPRは野上さんの確認後（勝手に出さない）。

## 目標の仮の値

| 項目 | 目標 |
|---|---|
| 1ラウンドの長さ | 20〜40秒（`仕様.md` の「まだ決めていないこと」には10〜30秒とある。遊んで決める） |
| 上手なボットの勝率 | 下手なボットの2倍以上（運だけで決まらない） |
| 引き分け | 10%未満 |
| 開始10秒以内の脱落 | ほぼゼロ |

## 準備でわかったこと（コードを読んだ結果）

- 動きは純粋な関数 `step(state, inputs, dt)`（`step.ts`）なので、画面なしで高速に回せる。入力は `{ [playerId]: { left, right, jump } }`、固定の刻みは `FIXED_DT = 1/60`
- 状態は `createMagmaState(playerIds, seed)` で作る。同じ seed なら同じステージ
- 終わりは `state.finished`、勝者は `state.winners`、脱落の記録は `state.survival.eliminated`（`at` が脱落時刻）
- 物理は `src/engine/jumper.ts`：ジャンプ最高点 750²/(2×2000) ≒ 140px、横 208px/秒
- 調整する値は `constants.ts`：`SCROLL`（30px/秒から始まり40秒で150、58秒で260）、`MAGMA_DEPTH_*`、`HARD_HEIGHT`（4000）、`MAX_RISE`（105）、`MAX_EDGE_GAP`（90）
- 既存テスト：`stage.test.ts`（どの足場にも届く）、`step.test.ts`。調整後も通すこと
- 現在のブランチ：`feat/magma-rush`（コミット e13d380 まで。PR未作成）

## 次にやること（再開したらここから）

1. ボットのシミュレーションを作る。**プロジェクトの外（スクラッチパッド）に vitest の設定とテストを置き**、`npx vitest run --config <設定> --root <フォルダ>` で回す（プロジェクトにファイルが残らず、`npm test` にも混ざらない）。前回の計測用 `_一時作業/probe.test.ts` が残っているので参考にしてよい（自動操作のボットは約10秒で落ちた）
   - 上手：次に乗る足場を選んで最短で跳び移る／普通：反応が遅く、たまにミスする／下手：ミスが多い
2. 現状の数字を測って、このファイルの「周回の記録」に **周0（現状）** として書く
3. 1周ずつ調整して、10周までくり返す

## 周回の記録

測定方法：4人（上手2・普通1・下手1のボット）で150試合。ボットのコードは `ボット計測.md` に控えてある。数字は1ラウンドの長さ（25%点・中央・75%点）、引き分け率、勝率（引き分けは山分け）、10秒以内に脱落した割合。

| 周 | 変えたこと | 長さ(中央) | 引き分け | 勝率 上手/普通/下手 | 10秒以内脱落 上手/普通/下手 |
|---|---|---|---|---|---|
| 0 | 現状（※ボットに不具合あり。参考値） | 19秒 | 8% | 40/19/1 | 3/30/63% |
| 1 | 速さ 30→25 加速 3→2.2、上限 150→130、2段目 6→5・260→240 | 21秒 | 9% | 31/34/3 | 2/14/55% |
| 2 | 難しくなる高さ 4000→3000、足場の幅を約15px狭く | 20秒 | 12% | 37/23/2 | 1/13/54% |
| 3 | 1段目の加速 2.2→1.6 | 21秒 | 9% | 35/29/1 | 1/9/54% |
| （ボット修正） | 着地したら狙いを選び直す（着地直後に古い狙いで跳び続けて動けなくなる不具合を直した） | 25秒 | 3% | 39/21/1 | 1/4/64% |
| 4 | 開始の速さ 25→20、最初の「足場が多い段」3→5段 | 28秒 | 5% | 38/24/0 | 0/1/49% |

周0〜3の数字は不具合のあるボットで測ったため、傾向だけの参考。
周4の時点で `npm test`（215件）・`npm run build` は通過。

## 気づいたこと

- 周0〜3は、ボットが着地直後に古い狙いで同じ場所を跳び続けて動けなくなっていた。「マグマの速さの壁で決まる」ように見えたのはボットの不具合だった
- 下手なボット（反応0.3秒・12%でミス）は半分が10秒以内に落ちる。実際の人間はもっと上手なはずだが、初心者でも序盤は落ちにくくしたい
